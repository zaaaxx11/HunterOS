# U2U dhcp2p 2026-08 — Hunt Detail (Go chi + Postgres + Redis REST IP allocator)

Static review of `/root/u2u-hunt/dhcp2p` (Clean Architecture, chi router, pgx + sqlc, Redis cache, Uber Fx). Task was architecture/protocol mapping ("Agent 1 ARCHITECT"), not exploit confirmation — findings are file:line static with severity + exploit reasoning. Full protocol map + attack surface written to `/root/u2u-hunt/reports/agent1-1-protocol-map.md` and `agent1-2-attacksurface.md`.

## What the thing actually is
NOT DHCP (no UDP 67/68 broadcast). REST API mapping monotonically-incremented `token_id` (int64) → IPs in `10.0.0.0/8` partial pool (~260k, `max_token_id=168162304`, migration `20251003103548.sql:7`; `last_token_id` starts 167902209). Token↔IP math in `internal/app/application/utils/ip.go:7-38` (`token = base + 254*blockIndex + host`, skip .0/.255). "P2P" in the name is only the auth key format (libp2p secp256k1) — allocation is 100% centralized.

## Auth flow (challenge-response)
1. `POST /request-auth` with `X-Pubkey` header → server derives peerID from pubkey (`internal/app/application/utils/nonce.go:8-20` via `peer.IDFromPublicKey`), returns UUID nonce (`internal/app/application/services/auth.go:23-41`).
2. Client signs `sha256.Sum256([]byte(nonceID))` (`internal/app/application/services/auth.go:48` — THE payload, nothing else).
3. Protected calls send `X-Pubkey` + `X-Nonce` + `X-Signature` headers → `WithAuth` middleware (`internal/app/adapters/handlers/http/middleware/auth.go:19-96`) → verify sig (`internal/app/adapters/auth/libp2p/signature.go:20-34`) → `GetNonce` + `ConsumeNonce` (`internal/app/application/services/nonce.go:31-56`) → peerID into context.

Route table (`internal/app/adapters/handlers/http/router.go:18-59`): protected = `/allocate-ip`, `/renew-lease`, `/release-lease`; PUBLIC = `/request-auth`, `/health`, `/ready`, AND BOTH lease lookups.

## Findings (file:line verified)

### 1. Pool starvation via Sybil — HIGH
- No allowlist/stake/Sybil-resistance anywhere: keypair generation is free and unlimited, one `POST /allocate-ip` per keypair.
- Pool cap: `max_token_id=168162304` → ~260k IPs (migration `20251003103548.sql:7`).
- 1 lease per peer enforced at `internal/app/application/services/lease.go:33-36` (`GetLeaseByPeerID` early-return), but nothing caps distinct peers.
- Rate limit: 100 req/min per IP default (`internal/app/infrastructure/config/config.go:90`) — slows, doesn't stop (100 IPs × 100 = 10k leases/min; pool gone in ~26 min). Attacker renews forever (`/renew-lease` no frequency cap; SQL `queries.sql:45-50` only checks token+peer+not-expired).
- Amplifier: NO lease sweeper job — expired leases only recycled via `FindExpiredLeaseForReuse` (`queries.sql:29-35`). If attacker renews, nothing expires → `AllocateNewLease` fails once counter hits max (`queries.sql:57-61` `WHERE last_token_id < max_token_id`) → newcomers locked out permanently. Only cleanup job is for NONCES (`internal/app/application/jobs/nonce.go:39-71`).

### 2. Unauthenticated lease enumeration — MEDIUM (recon gold)
- `router.go:46-47`: `GET /lease/peer-id/{peerID}` and `GET /lease/token-id/{tokenID}` mounted OUTSIDE the auth group. Anyone sweeps tokenID 167902209..168162304 → full token↔peerID↔expiry map of the overlay network. Rate-limited per IP only.
- Both queries only return non-expired rows (`queries.sql:19-27`), so the map is always live.

### 3. Rate limiter bypass + reset windows — MEDIUM (config-dependent)
- `internal/app/adapters/handlers/http/middleware/rate_limiter.go:80-138` `extractClientIP` trusts `X-Real-IP`/`X-Forwarded-For` if RemoteAddr matches `RateLimitTrustedProxies` (CIDR-aware, `isTrustedProxy` lines 116-138). Default empty = safe; one wide CIDR (`0.0.0.0/0`) = rotate fake IP per request, limiter dead.
- `cleanupUnusedLimiters` (lines 69-77) deletes ALL limiters every 5 min — synchronized burst window for every client at each cleanup tick.

### 4. Weak signature payload / no domain separation — MEDIUM (design)
- `services/auth.go:48`: signed payload = `sha256(nonceID)` only. No server identity, no method/URI binding, no timestamp. Signature+nonce pair authorizes ANY protected endpoint while nonce is unconsumed. Cross-instance replay works if two dhcp2p deployments ever share a nonce (UUID v4 → practically safe, architecturally wrong).

### 5. Nonce TOCTOU + cache incoherence — LOW
- `services/nonce.go:31-56`: verify signature FIRST, then `GetNonce`, then `ConsumeNonce` — three separate steps. DB is final arbiter (`queries.sql:10-14` `UPDATE ... WHERE used=false AND expires_at > now()` atomic) so no auth bypass, but error-path differences = oracle distinguishing valid-used vs invalid nonce.
- `internal/app/adapters/repositories/hybrid/nonce.go:67-69`: `DeleteNonce` failure after consume is only Warn-logged → used nonce stays in Redis → replays pass cache, die at DB. Noise, not exploit.

### 6. Error oracle — LOW
- `internal/app/domain/errors/app_error.go:45-62` maps distinct AppError types to 400/401/404/409 — attacker can tell exactly which validation stage failed (header? base64? signature? nonce? lease?).

### 7. SPOFs (architecture-level)
- `alloc_state` row id=1 (`queries.sql:57-61`): single-row UPDATE = global mutex for all new allocations. DB down = no new leases, ever.
- No TLS in app (`internal/app/infrastructure/server/http.go:19-45` plain `http.Server`); security.go:67 checks `r.TLS != nil` for HSTS → expects reverse proxy. Direct exposure = auth headers (`X-Pubkey`/`X-Signature`) in plaintext → sniff → replay within nonce TTL.
- Retry sleeps in allocation loop (`services/lease.go:55,80` up to ~3s/request) × 25 DB conns (`config.go:82`) = contention amplifier under flood.

## Verified SAFE (don't report)
- SQLi: all queries parameterized via sqlc (`queries.sql.go` generated).
- Double-pick race on reuse: `FOR UPDATE SKIP LOCKED` (`queries.sql:35`) + same-tx UPDATE.
- Nonce double-spend: atomic `UPDATE ... WHERE used=false`.
- Peer-binding on renew/release: `WHERE token_id=$1 AND peer_id=$2` in SQL (`queries.sql:49,66`) — peerID comes from auth context (`error_handling.go:86-95` `ValidatePeerIDFromContext`), not from request body → can't act on others' leases.
- Release is soft (`SET expires_at = now()`, `queries.sql:63-66`) — immediately reusable, but that's intended churn.
- `ReuseLease` (`queries.sql:37-43`) has no expiry re-check in WHERE, but row was locked FOR UPDATE in the same tx (`postgres/lease.go:28-56`) → safe.
