### Strapi V5 + Vite Dev-Server: the `?raw??` bypass family (Colb/flogi 2026-09-05)
**When a Strapi v5 admin serves `/admin/@vite/client` 200, it runs Vite DEV in production — that box leaks by default.** Exploit order that worked end-to-end (read-only, live-verified): (1) `GET /admin/.env?raw??` — the DOUBLE `??` suffix bypasses fs.deny where `?raw`/`?import` alone return SPA HTML; response is `text/javascript` wrapping the real .env in `export default "..."` → grep `ADMIN_JWT_SECRET`, `APP_KEYS`, `API_TOKEN_SALT`. (2) `GET /admin/.tmp/data.db` — full SQLite (admin bcrypt hashes, plaintext reset/registration tokens). (3) `GET /admin/@fs/<ABS>?raw??` — arbitrary system file read: `/etc/nginx/.htpasswd-*`, `/home/ubuntu/.bash_history` (vendor ops history: plaintext `strapi admin:create-user --password '...'` lines = password-pattern archaeology, internal port map from `proxy_pass 127.0.0.1:*`, staff SSH IP from `/proc/self/environ`), `.ssh/authorized_keys`, `/etc/hosts`. (4) **Forge admin JWT from the leaked secret** (HS256, payload `{"id":<admin_id>,"iat":now,"exp":now+7d}`) → `/admin/users/me` 200 = instant Super Admin, no login, no mail traces. (5) Forgot-password (`POST /admin/forgot-password` → 204) still writes a FRESH plaintext `reset_password_token` into the readable data.db — diff token column before/after = full-chain capability proof WITHOUT executing the reset.
**Patch-verification trap (Colb re-test):** the client (cms.colb.finance) properly patched = dev-server gone, static admin bundle, all doors HTML fallback (~260 bypass attempts dead), passwords AND ADMIN_JWT_SECRET rotated, old reset/registration tokens consumed, validator now distinguishes valid-shape vs garbage tokens ("Invalid registration info" vs "Invalid registrationToken" = token lookup runs first, tokens dead). BUT **the vendor's OTHER clients on the same template stayed unpatched** (to-cms.flogi.app) — pivot to vendor domain via crt.sh + the client's own vhost often present in the vendor's leaked `vite.server.allowedHosts` (from old `config/server.ts`: `colb-cms.flogi.app`). CF 526/502 hosts = alive-but-miswired origins: stage the full chain script and poll, don't mark BLOCKED.

### Django DEBUG=True in production = settings-table disclosure on ANY 500 (gorealtime 2026-09-05)
Any 500/exception page dumps stack traces (app path `/opt/terra/playpos`, Python version) AND the settings table where DB ENGINE/NAME/USER/HOST appear in cleartext (`<REDACTED-DB-USER>` = client owner's shared-hosting DB user) while SECRET_KEY-class values render masked `****`. Even masked, it maps the whole backend (FCM keys, Redis backend, JWT lifetimes, middleware list). `DisallowedHost at /` on sibling hostnames proves one debug-mode Django serves MANY client vhosts — enumerate clients via crt.sh on the platform domain (gorealtime.io → 15+ restaurant POS clients). Find the real API base from a CRA bundle by grepping ALL URL literals (filter reactjs/npmjs/momentjs/ckeditor noise) — REACT_APP_* strings don't survive builds; full `main.*.js` download needed (watch urllib maxb truncation at 800KB).

### Chia Data Layer: SSRF via unvalidated mirror URLs
Data Layer HTTP server (port 8562) is publicly accessible. Mirror URLs from `add_mirror()` are stored on-chain and used by `http_download()` **without ANY validation**. Attacker with a store (~0.001 XCH) can set mirror to cloud metadata endpoints (169.254.169.254, metadata.google.internal) and steal credentials from nodes syncing the store. Test with `http_download(ServerInfo(url="http://169.254.169.254/latest/meta-data/iam/security-credentials/"), ...)`. See `references/chia-data-layer-ssrf-2026-08.md` (preserved at examples/hunts/cdc/cdc-web-app-bug-bounty/references/chia-data-layer-ssrf-2026-08.md).
