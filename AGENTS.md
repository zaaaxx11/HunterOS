# AGENTS.md

Instructions for any agent harness (Claude Code, ZCode, or a generic
skill-loading tool) working in this repository.

## Layout

- `app/` is the Python package `huntos` (stdlib only). The `hunt` CLI is the
  single write door to the SQLite ledger.
- `app/src/huntos/_data/` holds the doctrine corpus: `idea/` (IDEA.md,
  HUNT-BRIDGE.md, skills), `roles/`, `hooks/`, `bin/`.
- The repo root is the plugin. Its skill tree and doctrine card are
  generated by `scripts/build_plugin.py`; commands, hooks, and the MCP server
  are hand-written.
- `docs/PLUGIN.md` describes install, gates, and the verification steps.

## Rules for agents

1. Do not run active testing against any target until the owner has approved
   rules of engagement (RoE) in writing. Record the approved RoE with
   `hunt target roe` before any active action.
2. Write findings, leads, and verification results only through `hunt` (or the
   `hunt_*` MCP tools that wrap it). Do not edit the ledger directly.
3. Do not claim `PROVEN`, `EXPLOITABLE`, or admin takeover without a bound
   finding or lead ID in the ledger.
4. Never fabricate command output. If a step did not run, say so.
5. Do not commit secrets. CI scans tracked files for secret patterns.

## Verify before you finish

```sh
PYTHONPATH=app/src python -m pytest tests/smoke/ test/tests/ -q
python scripts/build_plugin.py --check
```

If you changed the installer corpus, run `python scripts/build_plugin.py` to
regenerate the plugin tree, then run the check again.
